# Prompt 2: Set up the structure

Run this after your `about-me.md` exists. It builds the simple operating structure
around you. Three homes for information, nothing more.

The one idea worth understanding before you run it:

**Slow vs fast.** Two kinds of context, kept apart.
- *Slow* = what things **are** (who a company is, who a person is). Changes rarely.
- *Fast* = what is **happening now** (tasks, this week's status, decisions). Changes daily.

Mixing them is why most people's notes rot. Reference goes in one place, live state
in another.

Paste this in:

```text
Set up a simple operating structure in this folder. Three things, nothing more:

1. TASKS.md at the root: every open task across everything, grouped by area or
   company, newest first in each group. Open items only. This is not a journal,
   completed stuff comes off it.

2. A folder per company / client / area I work on, each with a CLAUDE.md inside.
   That CLAUDE.md holds two things: durable facts about what this thing IS, and a
   "Current State" block (status, last contact, next action, open threads). Current
   state gets overwritten as reality changes, never stacked into a pile of dated entries.

3. An empty debrief-history.log at the root: the append-only journal my debrief
   skill will write to. Just create it.

Read my about-me first. From it, set up a CLAUDE.md folder for each area you can
already see I work across, fill in what you know, mark guesses with [confirm]. Ask
me which areas to create if it's not obvious.

The one rule that stops this rotting: current state is overwritten in place,
history goes in the log, open tasks live in TASKS.md. Three homes, never mixed.

Show me the tree before creating anything.
```

## Don't front-load it

You need `about-me.md`, one company `CLAUDE.md`, and `TASKS.md` on day one. Add
more company files and the history log as you hit the need. A scaffold you grow
into beats ten empty folders you abandon.
