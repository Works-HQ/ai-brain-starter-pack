# The 30-minute test

A brain is only useful if someone new can operate from it. Give a newcomer, human or AI, access to the folder. If they cannot understand the structure and begin useful work within 30 minutes, the structure is defective.

This test comes from `ocp.wiki`. This pack uses only that operability test, not the rest of the OCP framework.

## What operational means

Operational does not mean the newcomer has memorised the company. It means they can:

- find the root map and explain what lives where
- locate the context needed for one real task
- identify the current state and open work
- name the rules and approval boundaries that apply
- produce or file one useful output in the right place

Use a real task with a clear finish. Ask for a meeting note to be filed, a short brief to be drafted or the next actions to be identified from current context. Do not give a private tour that rescues the structure. The folder should do the explaining.

## Run it with a clean start

Choose someone who did not build the brain, or start a fresh AI session with no conversation history. Give them the same access a normal operator would have. Start the clock when they open the root.

Watch where they hesitate. Which file do they open first? Can they tell durable facts from current state? Do they know which task list is live? Can they see what the AI may draft and what a person must approve?

Record every question. A question that depends on genuinely private judgment is fair. A question about where files live, which version is current or how to complete a standard workflow exposes a gap in the brain.

Stop after 30 minutes. Do not stretch the test because the newcomer is nearly there. The deadline forces the structure to prove that it can route attention quickly.

## Fix the structure, not the newcomer

When the test fails, resist writing a longer onboarding guide first. Find the exact point of failure.

If they opened the wrong file, improve the root map. If they found several possible answers, name one authoritative home. If the useful fact was buried in a long document, distil it into the relevant brain file. If they knew the facts but not the action, improve the skill or operating instructions. If the folder required background knowledge held by one person, mine and file that knowledge.

Then run the test again with a clean newcomer.

The 30-minute limit is not a productivity boast. It is a design constraint. A working brain should reduce dependence on the person who assembled it. If that person must stand beside every new user and explain the filing system, the knowledge is still trapped in their head.

Passing the test means the structure can teach its own use. The newcomer finds the right context, respects the boundaries and starts real work without archaeology. That is the standard.
