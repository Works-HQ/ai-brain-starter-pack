# The one idea: files are memory

Your AI has no useful memory between fresh sessions unless you give it something durable to read. A long conversation can feel like memory, but the effect lives inside that conversation. Start again tomorrow and you are back to briefing a clever stranger.

Files change that.

A folder of plain markdown gives the AI a memory you can see, edit, move, back up and keep. The model may change. The tool may change. The files remain yours. Each new session can read the same context before work begins, so you stop rebuilding the background one prompt at a time.

That is the whole idea behind this pack: **files are memory**.

## Keep files, not perfect prompts

A prompt tells the AI what to do once. A file tells it what remains true across many jobs.

You could write a long prompt every time you need an email: who you are, what the business does, how you sound, what happened last week and what must happen next. Or you could keep those facts in a small set of files and ask for the email. The request gets shorter because the useful context already exists.

This changes where you put the effort. You still need clear instructions, but prompt cleverness stops carrying the whole load. The better question becomes: does the AI have the right files, and are those files current?

When an answer is generic, treat it as a diagnostic. Something may be missing, buried or stale. Fix the relevant file. The next task then starts from the improved version. One correction can improve every future session instead of rescuing one answer.

## A folder is not automatically a brain

Dumping every document you own into one directory gives you storage, not memory the AI can use well. The facts may be in there somewhere, mixed with duplicate drafts, old decisions and irrelevant detail. More context is not the same as better context.

Start with the documents you already have, then mine them for the signal. Pull out the facts, decisions, preferences and working rules that will matter again. Put those into short, scoped files. Keep the raw documents as source material, not as the only place the truth lives.

The result should work like a filing cabinet. A root file acts as the map. Smaller files hold the context for one area. The AI opens the right drawer for the job instead of tipping the whole cabinet onto the desk.

## The memory has to stay alive

A file can be durable and still be wrong. If your priorities change but the file does not, the AI will confidently use old context. Stale memory is often worse than no memory because it still looks authoritative.

Build maintenance into the work. Debrief captures what happened and updates the current state. Reflect captures what you learned about working better. You review the proposed changes before they are saved. The AI helps maintain the brain, but it does not get to rewrite the truth unchecked.

Start small. One context file, one task list and one history log are enough. Use them on real work. When the AI lacks something important, add the smallest useful file or fact. When a file stops helping, clean it up.

Build good files. Keep them current. Let every session begin from what the last one learned.
