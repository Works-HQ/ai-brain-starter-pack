# Session 2: your company brain

**Length:** 240 minutes, including one 15-minute break

**Requirement:** Session 1 completed, or equivalent experience with standing context, routed working files, approval-gated writes, and at least one real debrief.

**Outcome:** Every participant leaves with a reviewed `brain/Company.md` mined from real documents, one useful People file, the operating layer stood up, and a weekly rhythm scheduled.

## 0 to 20 min: reconnect the two levels

Review what the personal level proved: the agent can use standing context, route live work, and wait for approval. Introduce the company split between slow brain context and the fast operating system.

Ask participants to name the company scope they will use today and the human reviewer responsible for accepting brain facts.

**You know it worked when:** Everyone can explain the difference between `brain/` and `operating-system/`, and has chosen one company scope.

## 20 to 40 min: deploy the company package

Participants follow `company/README.md` to copy the company package and shared skills into a new deployed root. They fill the root context placeholders and create live operating files from the supplied templates.

Check that `CLAUDE.md` and `AGENTS.md` remain identical.

**You know it worked when:** The deployed folder contains the root context files, `brain/`, `operating-system/`, `prompts/`, and `skills/`, with live operating files ready for use.

## 40 to 60 min: source safety and document selection

Participants confirm they are using copies and are authorised to process them. They put at least 10 real documents into `brain/_source-docs/`.

Ask them to include different evidence types rather than 10 versions of the same deck. They should identify any sensitive areas that require extra review.

**You know it worked when:** At least 10 permitted source copies are present, originals remain elsewhere, and the participant can name the review boundary.

## 60 to 85 min: inventory the source set

Participants run only the inventory stage of `prompts/mine-your-docs.md`. The agent groups sources by company and person using filenames and a light read.

They choose the smallest source subset that can support the first `brain/Company.md`. Do not deep-read unrelated documents.

**You know it worked when:** The inventory is clear, the selected source set is bounded, and no source file has changed.

## 85 to 120 min: mine brain/Company.md

The agent drafts the company file from the selected sources, citing source filenames and marking uncertain claims with `[confirm]`. Participants compare the draft with the evidence and direct knowledge.

Remove pitch language, unsupported conclusions, and facts that belong in current context rather than the durable brain. Approve the file only after this review.

**You know it worked when:** `brain/Company.md` contains sourced, reviewed company facts and clearly marked uncertainty, with no invented claims.

## 120 to 135 min: break

Ask participants to leave their agent stopped. This is a human break, not unattended processing time.

**You know it worked when:** Nobody has left an agent making unsupervised writes.

## 135 to 165 min: create one People file

Participants select one person who matters to current work. The agent drafts `brain/People/<name>.md` using the template, source evidence, and the participant's direct knowledge.

Keep it useful and appropriate. Include role, working preferences, priorities, relevant history, and current commitments. Remove gossip, speculation, and sensitive detail that does not serve the work.

**You know it worked when:** One reviewed People file improves a real draft or meeting-preparation question without relying on guesswork.

## 165 to 190 min: connect the operating layer

Participants fill `current-context.md` and `GLOBAL_TASKS.md` with today's true state. They identify where decisions, waiting items, debriefs, meeting notes, reflections, and weekly updates will go.

Run a read-only morning sweep to test routing. Do not save an extra output file during this block.

**You know it worked when:** The sweep reads the correct brain and operating files, produces a useful plan, and changes no files.

## 190 to 215 min: test the weekly loop

Participants run a draft weekly update and a weekly reflect review. They inspect both proposals, correct the inputs if the output is weak, and approve only useful changes.

The exercise should expose missing context. Add a verified fact to the correct file rather than compensating with a longer prompt.

**You know it worked when:** The weekly update reflects real progress and open loops, the reflection names a concrete system improvement, and each approved write lands in its defined home.

## 215 to 230 min: schedule the rhythm

Participants put a recurring weekly review in the calendar used by the company. The event includes the manual sequence: review current context and tasks, run the weekly update, run reflect, and check decisions and waiting items.

They also choose who reviews proposed brain changes. No agent action is scheduled yet.

**You know it worked when:** A real recurring calendar event exists with an owner, a review sequence, and a human approval point.

## 230 to 240 min: final proof

Ask each participant to give the agent one real company question. The answer should use `brain/Company.md`, the People file when relevant, and current operating context without searching the raw source dump.

Close with the four hard rules and the requirement to run the weekly rhythm manually twice before automating any part.

**You know it worked when:** The answer is grounded in the refined files, the source documents remain unchanged, all four outcomes exist, and the participant knows the next review date.
