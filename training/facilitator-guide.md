# Facilitator guide

This guide helps you run the two sessions with an accelerator cohort, sales team, operator group, or mixed room. Session 1 builds the personal level. Session 2 builds the company level from real documents.

The sessions are practical. Participants leave with working files, not a set of notes about files they might create later.

## Outcomes

By the end of Session 1, each participant has:

- a useful `about-me.md`
- the three homes stood up
- the shared skills available
- one real debrief reviewed and filed

By the end of Session 2, each participant has:

- a mined `brain/Company.md` based on real documents
- one useful file in `brain/People/`
- the company operating files in place
- a weekly review scheduled

Session 2 requires Session 1 or equivalent experience. Someone who has never reviewed an agent's file writes will struggle to judge a company brain safely.

## Prerequisites

Send these requirements before the session:

- a laptop with charger
- an AI agent installed and tested
- a folder the agent can read and write
- permission to use the selected documents with that tool
- one real meeting note or work note for Session 1
- at least 10 real company documents for Session 2

Ask participants to bring copies, not the only copy, of every source document. The company session works best with a mix of strategy, product, customer, sales, role, and recent operating material.

If company material cannot be used in the room, provide a fictional document set. Make it clear that this teaches the workflow but does not produce a deployable company brain.

## Room setup

- Seat people where screens are easy to see without forcing public sharing.
- Put the session plan and exact prompts on a shared screen.
- Provide a visible timer for each block.
- Leave enough space for quiet individual work.
- Use pairs for checks, but never require someone to reveal private source content.
- Have one facilitator for roughly every 12 participants if the room includes first-time terminal users.

Test the venue network, agent login, local file access, and copy-paste before participants arrive. Do not spend the teaching block discovering that half the room cannot open a folder.

## How to run Session 1

Keep the first system small. Participants need one area, one real note, and the two core skills. Redirect anyone building a complete folder hierarchy before their first debrief.

During the about-me block, remind the room that the agent drafts and the participant decides. A useful file contains concrete working context. It does not need a polished life story.

During the debrief block, slow down. Ask participants to inspect each proposed destination before approval. The important learning is not that the agent can write. It is that history, current state, and tasks land in different homes.

Finish with a quick proof: close the immediate chat context, start a fresh run if time allows, and ask the agent to state who the participant is and what happens next in the selected area.

## How to run Session 2

Start with source safety and access. Participants should know which documents are copies, what the agent can read, and who is responsible for reviewing extracted facts.

Mine one company and one person only. Breadth is tempting, especially when the inventory finds many topics. A narrow brain that is checked against its sources is more useful than a large brain full of guesses.

Use the document inventory as a decision point. Participants choose which sources matter before deep reading begins. Ask them to watch for conflicts between documents and to keep `[confirm]` markers until a human resolves them.

End by scheduling the weekly rhythm in a real calendar. The system will go stale if the room treats the workshop as a one-off build.

## Common stumbles

### The agent cannot see the folder

Stop and fix permissions or working-directory selection. Do not compensate by pasting the whole pack into chat. The point is a file-based system the agent can revisit.

### The about-me draft is generic

Ask for one writing sample, the participant's actual responsibilities, and three concrete preferences. Remove motivational filler. Keep only context that would change the agent's work.

### Everything goes into one file

Return to the routing rule. Current state is replaced, history appends, and tasks stay open-only. In company mode, durable company facts belong in the brain and live work belongs in the operating system.

### The room starts automating

Bring the workflow back to manual review. The group needs two useful manual runs before it can judge what should be scheduled.

### The document dump is too large

Inventory first, then select a small source set for the first company file. Do not deep-read everything because it happens to be available.

### The mined brain states guesses as facts

Reject the write. Require source filenames, mark uncertainty with `[confirm]`, and ask the participant to resolve the claim. Trust matters more than coverage.

### Participants skip the real debrief

Give them five quiet minutes to choose a real note. A toy example proves that the syntax works. A real debrief proves that the system helps.

## Facilitation rules

- The AI drafts, the participant approves.
- Never ask the room to expose private documents on the shared screen.
- Keep source documents read-only.
- Treat legal, financial, people, and other sensitive claims as requiring human review.
- Keep each participant on the smallest structure that can complete the stated outcome.
- Do not call the session complete until the checkpoint files exist and contain reviewed content.
